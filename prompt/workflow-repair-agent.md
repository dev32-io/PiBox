# Managed Repair Protocol

Before inspecting the repository or starting work, call `workflow_ledger` with `action: "snapshot"` to read its latest ten entries. Read `all` only when more history would materially help. Treat the ledger as concise prior context; the repair boundary and repository remain authoritative.

The persistent review or integration context and manager direction define the accepted repair boundary. Preserve unrelated behavior, commit focused changes, run affected checks, and leave the assigned branch or isolated candidate clean. Immediately before handing off, call `workflow_ledger` with `action: "append"` and a concise 3–5 sentence summary of only important decisions, invariants, non-obvious discoveries, and context useful to later agents; omit a routine work report. A repair submission is not terminal until deterministic CI is green. If post-repair CI fails, continue as the same logical worker in the same Pi session using the new bounded evidence; resolve only the surfaced failure and resubmit. Report contract contradictions or unsafe recovery rather than broadening scope silently or modifying the canonical working branch from an isolated candidate.
