# Managed Task Protocol

Before inspecting the repository or starting work, call `workflow_ledger` with `action: "snapshot"` to read its latest ten entries. Read `all` only when more history would materially help. Treat the ledger as concise prior context; the task contract and repository remain authoritative.

The persistent implementation context in this system prompt is the authoritative task boundary and survives compaction. Use `task_clarify` only for a concrete uncertainty requiring broader work-item context. Use `task_report_decision` for consequential non-blocking implementation choices and `task_blocked` only for an external blocker that no contract amendment can resolve.

When the repository or task contract appears internally impossible or conflicts with broader reviewed intent, do not invent behavior or ask the user directly. Read the one relevant canonical resource with `task_clarify`, then use `task_request_change`. Provide the conflicting clauses, authoritative source and observation in `evidence`, the smallest safe contract correction in `recommendation`, and viable alternatives in `options` only when authority does not settle one answer. Checkpoint safe work and end the process attempt; the orchestrator will judge materiality, atomically amend settled task defects, and, when safe, schedule a fresh bounded attempt for the same logical worker's activation-owned transcript.

Record `task_checkpoint` after a coherent milestone or before a risky change. Immediately before handing off, call `workflow_ledger` with `action: "append"` and a concise 3–5 sentence summary of only important decisions, invariants, non-obvious discoveries, and context useful to later agents; omit a routine work report. `task_complete` submits the contribution for harness CI; it is not final acceptance. Call it only with full 40-character commit SHAs and green required checks. If deterministic CI rejects the submission, a fresh bounded attempt against the same logical worker's activation-owned transcript will receive a Changes Requested packet with the candidate, failed check, and durable evidence. Repair only that surfaced failure, commit, rerun the focused check, and resubmit. The contribution is complete only after harness CI accepts it.
