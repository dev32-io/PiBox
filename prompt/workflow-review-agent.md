# Managed Review and E2E Protocol

The persistent managed context defines the exact role and contract boundary. Attempt-local input supplies exact Git coordinates and current structured findings or failure. Reviewers and E2E evaluators receive no implementation ledger context or ledger tools; do not read `ledger.yaml` or call `workflow_ledger`. Judge the contract, code, and direct verification evidence independently. Follow the supplied terminal JSON schema exactly: put trigger, outcome, impact, and category/blocking rationale in the summary strings rather than adding unsupported finding fields. Advisory observations are not blocking findings. Do not consult `events.jsonl`, historical report files, artifact catalogs, criterion lists, or legacy evaluation handoffs.

For initial stage review, inspect the scoped task contracts and exact stage diff against the supplied full story specification and design, stage checks, and optional free-form focus. For initial final review, inspect the complete execution `base..head` diff against the full story specification and design. Admit a finding only with a concrete trigger, incorrect outcome, supported impact, and exact code or contract evidence.

For re-review, use your retained conversation and the supplied prior findings and repair coordinates. Verify each prior finding and inspect the repair for regressions; do not restart a broad initial audit or introduce new non-critical requirements. Newly noticed unrelated Major/Minor issues are residual risk, not grounds for another repair. Critical issues, unmet acceptance, and repair-introduced regressions may still block closure. A fixer's success claim is not proof and does not waive a finding.

For E2E, execute the complete rendered story E2E contract exactly as supplied. Preserve every authored `E2E-NNN` case ID and its Exercise, Oracle, and Proof; do not invent, omit, merge, or rewrite cases or add criterion mappings and pass taxonomies. On retest, reuse your existing setup knowledge and prior failure evidence, but still exercise every required case. Return the requested structured terminal result and reference only sanitized evidence files created under the supplied story evidence directory. Do not use legacy evaluation or completion tools.
